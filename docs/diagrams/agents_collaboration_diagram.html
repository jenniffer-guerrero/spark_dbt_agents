Agents Collaboration Architecture

How specialized agents cooperate in this Spark incremental mapping project to implement logic, design and validate test cases, run repairs, and keep notebooks and documentation synchronized.

Data Engineer and Analytics Agent test_data Agent Explore Agent

Project Context

The project maintains an incremental mapping from REL_ID to REL_ID_REGIE_KLANT over a historical graph built from direct_bank and ggm_np. The delivery model requires strict consistency across Python transformation logic, update notebooks, origin notebook semantics, unit tests, notebook test cases, and user-facing documentation.

Agent Roles and Functional Scope

Data Engineer and Analytics Agent

Primary implementation and orchestration agent
  • Implements and refactors Spark transformation logic.
  • Performs lineage and impact analysis for model changes.
  • Synchronizes logic with update and origin notebooks.
  • Coordinates validation workflow and final consistency checks.
  • Ensures documentation updates match final behavior.

test_data Agent

Stateful testing and delta-verification specialist
  • Designs high-value stateful mutation scenarios.
  • Defines expected inserted and removed output deltas.
  • Validates idempotency and duplicate-safety behavior.
  • Detects mismatches between logic, unit tests, notebook tests, and docs.
  • Proposes concrete file-level corrections when failures appear.

Explore Agent

Fast read-only discovery and context accelerator
  • Finds relevant symbols, files, and references quickly.
  • Supports impact scoping before edits.
  • Reduces navigation overhead in large changes.
  • Helps verify coverage of cross-file updates.
  • Improves throughput without modifying source artifacts.

How Agents Interact in the Change Lifecycle

Step 1

Scope

Data Engineer analyzes requested business-rule or graph-semantic change and impacted artifacts.

Step 2

Implement

Update Python logic and synchronize notebook logic for update and, when needed, origin flow.

Step 3

Design Tests

Invoke test_data to validate scenario deltas and detect missing or incorrect test coverage.

Step 4

Repair and Align

Fix unit tests and notebook tests until behavior and expectations are consistent.

Step 5

Validate

Run pytest and replay impacted notebook cases, including edge and seed eligibility checks.

Step 6

Document

Update diagrams and user notes so documented behavior matches the shipped implementation.

Functional Benefits of Agent-Based Development

Advantages

  • Clear specialization reduces context switching and improves quality.
  • Stateful testing discipline catches regressions in incremental behavior.
  • Mandatory synchronization lowers drift between code, notebooks, tests, and docs.
  • Faster triage and repair loops with explicit failure classification.
  • Better auditability of why a change was made and how it was validated.

Trade-offs and Considerations

  • More process overhead for small one-line changes.
  • Requires discipline to keep prompts and agent definitions up to date.
  • Notebook and unit-test parity can drift if synchronization is skipped.
  • Long validation cycles may increase turnaround for complex scenarios.
  • Environment instability can mask logic defects unless runtime issues are isolated first.
Recommended practice: treat every logic update as a full lifecycle change (implementation, test design, validation, and documentation) rather than as an isolated code patch.
