== PURPOSE ==

These prompts recreate the agent and skills infrastructure from scratch.
Run them in order (1 → 2 → 3 → 4) before running notebook_logic_generation_prompts.txt.
All skill definitions, schemas, and protocols live in .agent-skills.md — prompts reference
them by name and do not repeat their content.


== PROMPT 1 — Create .agent-skills.md ==

Create the file `.agent-skills.md` in the repository root using YAML frontmatter.
All content must be in English.

Define the following skills. For each skill write a description, then enumerate
its capabilities, patterns, or sub-sections with enough detail that an agent can
implement correct, consistent behavior without reading any other file.

Skills to define:

  spark
    - PySpark and Spark SQL transformations.
    - Modular, testable, Databricks runtime-compatible code.

  incremental_mapping
    - Source tables, state tables, and output table with column schemas.
    - Seed selection rule (drc_bnk_f, edl_valid_to_dts sentinel).
      - Winner rule (latest seed_valid_from_dts, then min numeric seed, lexical fallback).
    - The six phases: build snapshot, detect deltas, compute impact, recompute,
      merge and enforce, persist.
    - BFS parameters (max_iter, checkpoint_every).
    - Observability dict schema.

  spark_runtime_reliability
    - Exact in-place overwrite sequence (materialize replacement, INSERT OVERWRITE same table, refresh catalog).
    - Checkpointing pattern for iterative BFS.
    - Cache invalidation after writes.
    - Cheap emptiness check (_has_rows with limit(1)).
    - Local metastore and Java runtime constraints.

  notebook_engineering
    - Separation of update logic notebook from test notebook.
    - JSON-based code cell loading (no nbformat dependency) — include code snippet.
    - reload_update_logic(namespace) utility — include full implementation.
    - One markdown + one code cell per phase or test case.

  stateful_test_design
    - feedback_schema dict (all fields, types, and allowed values).
    - Required helper function signatures:
        pair_set, assert_delta, assert_output_has_no_duplicates,
        make_feedback, show_case_tables.
    - per_case_sequence (numbered steps 1–10).
    - baseline_management functions:
        snapshot_baseline, restore_baseline, reset_sequence_to_baseline.

  agent_repair_protocol
    - Trigger condition (failure_class == 'logic_defect').
    - max_retries = 2 and unresolved escalation.
    - Full call_repair_agent(feedback, update_nb_path) implementation:
        reads agent instructions and notebook JSON, calls Anthropic API
        (model from env ANTHROPIC_MODEL, default 'claude-opus-4-7'),
        locates and replaces the target code cell, writes notebook back to disk.
    - retry_sequence (attempt loop with reload and re-run).


== PROMPT 2 — Create data-engineer-analytics agent ==

Create the file `.github/agents/data-engineer-analytics.agent.md`.
All file content must be in English.

Frontmatter fields:
  name: Data Engineer & Analytics Agent
  description: (Spark engineering, incremental mappings, lineage, notebook hardening)
  argument-hint: (data domain, impacted tables, current behavior, expected output)
  user-invocable: true
  tools: [read, search, edit, execute, todo, agent]

Body must contain these sections and nothing else:

  Opening instruction:
    Read `.agent-skills.md` before any task. It is the source of truth for all
    skill definitions, patterns, and protocols.

  Skills table:
    Map each skill name to a one-line description of when to apply it.
    Skills: incremental_mapping, spark_runtime_reliability, notebook_engineering,
    stateful_test_design, agent_repair_protocol, spark.

  Scope:
    Build/refactor/review Spark logic. Lineage analysis.
    Test-driven development. Edge cases. Incremental recomputation.

  Repository Conventions:
    Reference .agent-skills.md for repository conventions.
    English-only for file content by default.
    Only allow non-English file content when explicitly requested by the user.
    Chat may follow user's language.

  Working Style (5 rules):
    Confirm assumptions. Minimal targeted changes. Add tests for non-trivial logic.
    Explain lineage impact. Document state-table implications for incremental changes.

  Mandatory Change Protocol (logic updates):
    Require synchronized updates for:
    - Python logic and impacted notebooks (`siebel_id_update.ipynb` and `siebel_id_origin.ipynb` when graph/business rules change).
    - Unit tests and notebook test cases (`tests/test_siebel_incremental.py`, `notebooks/siebel_id_test.ipynb`).
    - Documentation (`docs/diagrams/*`, and user-facing docs such as README when behavior changes).
    Must invoke `test_data` for scenario/delta validation and run both pytest and impacted notebook cases before finalizing.

  Continuous Data-Test Collaboration Loop (mandatory):
    For any fix/refactor/code change with behavioral impact:
    1) apply minimal change,
    2) invoke `test_data`,
    3) apply corrections returned by `test_data`,
    4) repeat steps 2-3 until `test_data` reports validated,
    5) then run final validations and finalize.
    This interaction must be continuous, not one-off.

  When Invoked for Repair:
    Follow .agent-skills.md / agent_repair_protocol.
    Return only the corrected Python source for the function named in suggested_fix.


== PROMPT 3 — Create test_data agent ==

Create the file `.github/agents/test_data.agent.md`.
All file content must be in English.

Frontmatter fields:
  name: test_data
  description: (stateful incremental tests, delta assertions, idempotency validation)
  tools: [read, search, execute, agent]

  Note: do NOT include a model field unless you have verified the model name exists.

Body must contain these sections and nothing else:

  Opening instruction:
    Read `.agent-skills.md` before any task. It is the source of truth for all
    skill definitions, protocols, schemas, and helper signatures.

  Skills table:
    Map each skill name to a one-line description of when to apply it.
    Skills: stateful_test_design, incremental_mapping, agent_repair_protocol,
    spark_runtime_reliability, notebook_engineering.

  Goals:
    Propose stateful mutation scenarios. Define expected delta before running.
    Cover both source systems (direct_bank, ggm_np mutation types).
    Apply winner rule from .agent-skills.md / incremental_mapping.

  Repair Delegation:
    On failure_class == 'logic_defect': follow .agent-skills.md / agent_repair_protocol.
    Use the `agent` tool to invoke data-engineer-analytics agent.
    Max 2 retries; escalate to 'unresolved' otherwise.

  Outcome Evaluation:
    Use feedback_schema and per_case_sequence from .agent-skills.md / stateful_test_design.
    Failure classes: logic_defect, data_precondition, environment_runtime.

  Constraints:
    Minimal and reproducible scenarios. Stateful runs.
    English outputs by default.
    Only allow non-English file output when explicitly requested by the user.

  Scenario Catalog:
    Seed creation/removal. Relationship rewiring. Duplicate rows. Cross-table
    insertions. Cross-source same-rel_id bridge connectivity. No-op idempotency reruns.

  Collaboration protocol for logic changes:
    Validate parity between code logic, unit tests, notebook tests, and documentation.
    When called by data-engineer-analytics, return concrete file-targeted corrections
    for tests, notebook test cases, and doc mismatches caused by logic updates.

  Continuous interaction contract with data-engineer-analytics:
    Work in an iterative cycle after each change from data-engineer-analytics.
    Return explicit status on every cycle: validated | needs_fixes | blocked_environment.
    If needs_fixes, provide concrete file-targeted edits for the next iteration.
    Continue cycles until validated or clearly blocked by environment/runtime.
