== PROMPT C — Create notebooks/siebel_id_test.ipynb ==

Create the stateful test notebook. All markdown and code comments in English.
This notebook loads and calls run_incremental_update from siebel_id_update.ipynb.

Baseline data:
  Load use_cases/siebel_id/input/direct_bank.csv → shebang.direct_bank
  Load use_cases/siebel_id/input/ggm_np.csv → shebang.ggm_np
  Use use_cases/siebel_id/input/output.csv to validate the initial sync result.

Notebook cells in this order:

  1. Markdown — intro: purpose, how to run, how to reset.
  2. Code — setup: Spark runtime, load siebel_id_update.ipynb via JSON loading
            (apply notebook_engineering: json_loading). Confirm run_incremental_update
            is callable.
  3. Code — baseline management: load fixture CSVs, snapshot_baseline,
            restore_baseline, reset_sequence_to_baseline
            (apply stateful_test_design: baseline_management).
  4. Code — assertion helpers: pair_set, assert_delta, assert_output_has_no_duplicates,
            make_feedback, show_case_tables
            (apply stateful_test_design: required_helpers).
  5. Code — repair helpers: call_repair_agent, reload_update_logic reference
            (apply agent_repair_protocol: call_repair_agent from .agent-skills.md).
  6. Code — initialization: reset_sequence_to_baseline, run initial sync, validate
            against output.csv, show baseline tables and stats.

  Then for each of the 11 cases below, one markdown cell (case name + what changes +
  expected delta) followed by one code cell (mutation + full per_case_sequence from
  .agent-skills.md / stateful_test_design, including repair loop on logic_defect):

  Case 1: Insert new active seed in direct_bank.
  Case 2: Flip existing seed drc_bnk_f Y -> N.
  Case 3: Reassign ggm_np rel_id for an existing ikb_no.
  Case 4: No-change idempotent rerun (expect zero delta).
  Case 5: Add new ikb_no to an existing rel_id.
  Case 6: Insert duplicate source row — output must not gain a duplicate pair.
  Case 7: Add new rel_id linked to an existing ikb_no already used by another rel_id.
  Case 8: Simultaneous insertions in both direct_bank and ggm_np sharing one identifier.
  Case 9: Insert direct_bank drc_bnk_f='N' plus ggm_np row sharing existing ikb_no and verify
        both rel_id values are connected and mapped through existing seed.
  Case 10: Add historical (closed) direct_bank row and verify rel_id appears in output REL_ID.
  Case 11: Add direct_bank row with drc_bnk_f='Y' but closed edl_valid_to_dts and verify
         it is not selected as REL_ID_REGIE_KLANT.

  For the markdown cell of each case, derive and write the expected_inserted and
  expected_removed pairs from the fixture data before the code cell runs.

Constraints:
  - Fully replayable via reset_sequence_to_baseline().
  - All source mutations use same-table overwrite fallback (spark_runtime_reliability).
  - Clear pass / fail / unresolved printed per case.
